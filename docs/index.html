unit tests and CI for Sigma detection rules · MIT · github.com/RedaKarrach/detforge

What this is for. A detection rule is a few lines that tell a security tool "alert when you see this". Teams write hundreds of them, paste them into their tools, and rarely look again. Months later a rule has quietly stopped working, or started alerting on normal work, and nobody knows. DetForge is the check: every rule keeps a few example attacks and a few normal events next to it, and they are re-run every time the rule changes. Like unit tests for code. If a rule breaks, the build fails before anyone ships it.

Eight questions, one command each. Run it, read what it prints, take the arrow down. Every line of output here is real. The test harness runs live, on the repository's real example events, in your browser.

Press enter, or tap the command line, to run the first one.

END OF TRANSMISSIONRun it yourself.

$ git clone https://github.com/RedaKarrach/detforge.git
$ cd detforge
$ python -m venv .venv && .venv\Scripts\activate   # Linux/macOS: source .venv/bin/activate
$ pip install -e ".[dev]"
$ detforge lint --offline
$ detforge test
$ detforge convert --target all
$ detforge coverage
$ detforge report

# your own rules: set these in pyproject.toml
[tool.detforge]
rules = "sigma/rules"
fixtures = "sigma/tests"
out = "build"

# writing a rule
1. rules/windows/<tactic>/<rule_name>.yml, with a technique tag and a tactic tag
2. tests/fixtures/<rule id>/tp.jsonl and tn.jsonl, two events each at least.
   make the tn events near misses, not noise. that is where rules break.
3. a row in docs/RULES.md: logic, false positives, evasions
4. detforge lint --offline && detforge test

# what it does not do
- fixtures prove the logic, not that your Sysmon writes those field names. export real events when you can.
- single-event rules only. no correlation.
- SQLite tests the rule's own field names. review the converted Splunk and Elastic queries in the SIEM.

# stack
pySigma (sqlite, splunk, elasticsearch backends) · Python 3.11+ · typer + rich · pytest · GitHub Actions
